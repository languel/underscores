# Canvas-first relationships and physics

Underscore API version 8 and scene-exchange version 10 introduce a solver-independent relationship graph at `underscore.relationshipGraph`. The graph persists world settings, systems, object bindings, populations, constraints, mappings, and endpoint references. An authored body’s settings and reset state live on its native Excalidraw object at `object.customData.physics`; Rapier handles, live poses, collision queues, checkpoints, stream samples, and grab joints are runtime-only.

## Runtime architecture

- Rapier 2D is pinned to `@dimforge/rapier2d-deterministic-compat@0.19.3`. It runs at a fixed 60 Hz in `physics.worker.js` and is initialized only after the first enabled Rapier system is created. Normal builds use a lazy worker asset; the single-file build embeds the worker and creates its Blob only on activation.
- `runtime-lite` population members keep only solver identity, pose, collider, tags, and render style. Their transferable pose buffer is painted by one imperative Canvas2D overlay without a React render loop.
- `authored-rigid` bodies remain selectable Excalidraw objects. Display poses are batched, non-history scene updates; scene serialization substitutes the authored reset transform until Apply pose is used.
- `authored-deformable` bodies remain canonical Underscore curves. The geometry adapter resolves stable anchor IDs and typed stream endpoints at display cadence while preserving reset geometry.
- The worker owns fixed-step accumulators, deterministic snapshots, transport checkpoints, bounded catch-up, collision queues, and pooled pose buffers. Paused systems do not send repeated pose buffers.

Each system has either an independent realtime clock or the Underscore music transport clock. Pause holds the evaluated pose. Reset restores the authored baseline. Apply pose commits the current rigid transforms and deformable geometry as one authored history change. Seeking a transport-clocked system restores an in-memory deterministic checkpoint and advances fixed steps to the target. Transport rewind controls, including `Shift+Left`, reset a transport-linked world together with the score; independent physics is unaffected.

**Live timeline preview** is an optional, browser-local Physics World setting and is off by default. When the world follows the music transport, it evaluates the current playhead by restoring and replaying deterministic checkpoints while the timeline drag is in progress. Scrub evaluations suppress collision, audio, and command routes so a visual preview has no side effects. Large seeks can be expensive, and deterministic results require authored or recorded timed inputs rather than live external streams.

## Graph model and endpoints

`relationshipGraph.version` is currently `4`. Its collections are `systems`, `bodies`, `populations`, `constraints`, and `mappings`. Runtime ownership allows one writer per object channel: rigid systems claim `transform`; live geometry systems claim `geometry`. Duplicate claims emit `physics.writer.conflict`. Missing objects or deleted stable anchors emit `physics.relationship.orphan`; affected graph items are disabled but retained for repair. Legacy collision `routes` migrate to compatible mapping targets on load and are retained only as a script compatibility view; new scene JSON writes canonical mappings.

Version 3 adds named **collision layers**. `world.collisionLayers.layers` is a stable stack of up to 15 named layers and `world.collisionLayers.matrix` is its symmetric, editable contact table. A body's `collisionLayers` array selects its memberships; the worker derives the Rapier group/mask pair when it loads the graph. The final Rapier bit is reserved internally for generated rope links, so rope self-contact never consumes an authored layer. An explicitly empty membership is valid and makes that body non-colliding without disabling its joints or queries. New worlds start with one **Default** layer and all contact pairs enabled, preserving ordinary all-to-all collisions. Bodies from earlier scenes deliberately keep their raw `collisionGroup` and `collisionMask` until they are assigned to the named stack, so migration never silently changes an existing simulation.

Endpoints can address a world point, object center or normalized object-local point, curve progress, canonical Bézier anchor by stable local ID, a rope control point, or a feature/value from a typed stream. Rope endpoints retain normalized arc-length `ropeProgress` and, once solved, generated-link identity; that keeps an axle or weld on the same folded rope point when its pose becomes the reset state. Canonical Bézier geometry is version 2. Existing anchors migrate to stable `anchor-N` IDs, and newly inserted anchors receive UUIDs. Copy/import remaps object references while retaining stable local anchors. When a rounded native line or freehand path becomes a rope, authoring samples its rendered cubic geometry rather than a sharp control-point approximation, so the source curve's visible shape is preserved.

## Canvas interaction

Open `/physics` (or `/relations`). The panel is an inspector and transport, not a node editor.

The Scene panel also exposes a **World** section. Gravity is authored in metres per second squared (default `0, -9.8`), viscosity is zero by default, and `Pixels per metre` controls the conversion into canvas coordinates. Since canvas Y grows downward, the conventional negative world-Y gravity falls downward in the drawing. `Sim speed` scales elapsed simulation time while the solver keeps its fixed cadence. Its compact controls play/pause, reset, and optionally sync all physics systems to the music transport; with sync active, either transport controls the other.

The Systems panel contains an opt-in **Physics debug overlay**. It draws diagnostic body bounds, actual collider geometry, labels, constraints, contacts, collision pulses, and force vectors in the same canvas/world coordinate system as the authored objects. One-sided constraints with a deliberate `None` endpoint still show their live attachment marker instead of disappearing from diagnostics. Labels prefer the canvas/outliner name, then the physics name, rather than exposing internal IDs. Each diagnostic category is independently toggled and accepts a theme-aware CSS color (including `object`, named colors, hex, and CSS functions). Its data is runtime-only and never serializes or exports. Visible debug strokes are also published as runtime-only line segments to the shader scene bridge, allowing an Inkwash node in **Physics debug** emitter mode to react to collider, constraint, contact, force, and trail drawings without creating canvas objects. With the overlay off, it does not collect or paint diagnostic primitives, so it adds no simulation or canvas rendering work.

The same diagnostic path can draw transient **trails**. Enable one on a body to follow its centre of mass; Axles and Welds can plot their body-A and body-B attachment points independently so real joint separation appears as two diverging traces. A standalone **Tracer** follows an object point without becoming a physics body. Trail color, opacity, and retained duration are debugging controls only: they do not alter the authored scene or solver. Comparing centre and attachment trails is useful when separating stable solver motion from a visible endpoint or rendered-shape offset.

There is a known presentation caveat for articulated freehand bodies. In the current diagnostic mobile, the Rapier anchors remained subpixel-stable while the visible freehand endpoints sometimes shimmered around them. At the default four solver iterations, the worst measured anchor error was about `0.99 px` for the heavily loaded freehand axle and below `0.38 px` for the other tested joints; at sixteen iterations the maxima fell below `0.025 px`. The larger apparent displacement of the orange debug squares is therefore not evidence that the joint is breaking: the overlay reads the newest worker pose in its own animation-frame loop, while Excalidraw applies body poses in a separate queued frame and may display the authored shape one rendered frame behind. Complex freehand rerasterization and their irregular convex hull/inertia can add visible shimmer, with a smaller genuine solver-compliance component. This is documented for a later rendering/solver pass; no corrective filtering is currently applied, and physics-generated event state should continue to use solver coordinates rather than screen-space marker alignment.

For a new or re-authored one-body **Axle**, if its marker contains the start or end of a line, arrow, or freehand body, authoring snaps that marker and its local anchor to the visible endpoint. This avoids an accidental nearby invisible pin that makes the visible tip orbit the axle. Existing pivots are left unchanged; reassign that axle to opt into the endpoint snap. Interior pivots retain their exact authored position.

Select a canvas object and use Shift-right-click → **Make Physics Body**, or run `/make body`. Underscore creates a default World system when the scene has none, infers a collider and material from the selected object, attaches an authored dynamic body, and opens the Physics inspector. Fixed walls, pins, and joints remain separate authoring steps.

Assigned objects own their authored body data at `object.customData.physics`. The Properties panel exposes its most useful fields in a pinned **Physics role** section, while the relationship graph retains only the stable object/system binding needed for constraints and routes. Rapier receives a derived runtime body definition. Older scenes may still contain `customData.underscorePhysics`; it is read as a legacy alias and replaced with `customData.physics` on the next body edit.

When two or more selected objects have a Physics role, Properties adds a **Shared physics** group. Mixed fields display as `Mixed` until authored; changing a shared field applies that value to every selected physics body in one graph and custom-data update. This includes body type, enabled/sensor state, tags, collider, friction, bounce, density, damping, collision skin, and collision-layer membership. The same batch behavior applies when an individual Physics-role card is edited while the multi-selection remains active. Objects without a Physics role are left untouched, and each body retains its unrelated material, collider, render, and authored reset settings.

Use **Physics → Collision layers** to name the world layers and enable or disable each layer pair. The matrix answers **which layers collide with which**; the **Belongs to layers** checkboxes on a body or rope answer **which layers that object contributes to**. A multi-selection applies the chosen membership set to every selected physics body. This makes a spool setup straightforward: assign the rope to `ropes`, assign the spool body to `spool`, enable `ropes × spool`, and disable `ropes × ropes` if the layer should never contact itself. One body can belong to more than one layer when it needs to interact with several groups.

While a world is paused, **Paused edits → Author reset pose** is the default: moving, resizing, rotating, or editing an authored rigid object updates its physics reset pose and inferred collider in both the graph and `customData.physics`. **Reset** returns to that latest paused arrangement; **Apply current pose** commits a running simulation pose in the same way. Choose **Keep reset pose** when you want temporary paused staging or a simulation experiment to return to a locked authored arrangement. Play and Reset flush a pending paused edit before talking to the worker, and worker graph loads are revision-guarded so an older async load cannot replace a newer authored scene. Closed, near-round freehand strokes infer solid circle colliders; other closed strokes infer convex colliders. Path bodies can choose **Bounding box**, **Bounding ellipse**, **Convex hull**, or **Path chain** in Physics Role. A Path chain is a compound run of rounded solid segments for fixed walls and moving bodies alike. Its physical width follows the canvas stroke width, and overlapping round endcaps keep sharp turns watertight for small bodies.

**Live pose** is a separate solver-driven manipulation mode. Enable it in Physics World—or press `\\` outside text entry—then pause the simulation (or set its time scale near zero), and drag either an authored body or an axle/weld pivot. The grab is full-strength at pointer speed while the solver performs bounded zero-gravity constraint iterations, so attached bodies propagate like an IK rig without advancing the public physics/transport clock. At timeline zero, releasing the grab promotes the solved result to the authored physics reset pose, so rewind returns to it. A rope-pivot release commits one synchronized final solver snapshot: the free rope path, World anchor, and rope-link attachment move together, with a final 96-iteration settle. Rope-bound pivot grabs cache the other attachment references and clamp unreachable targets to the authored rest length, keeping the rope from stretching or jittering when both ends are posed. Selected bodies and pivots remain owned by the native Excalidraw transform path, so box-selected group drags do not get stolen by the runtime grab handler. At any other time the result remains a temporary runtime pose; use **Apply pose** when that is the intended new reset baseline.

Box-selecting and translating a complete articulated subsystem is also an authored transform. The
canvas move updates every selected body's reset pose and every selected pivot's visible position as
one operation, then refreshes connected local anchors from the moved graph. During that handoff the
already-updated relationship graph is authoritative; stale per-object `customData.physics` from the
previous frame must not overwrite the new subsystem pose. This keeps World hinges, body-body Axles,
Welds, and their offsets intact whether Live Pose is enabled or disabled.

**Paused edits** concerns ordinary direct canvas transforms, not Live pose: **Author reset pose** saves a paused transform as the next Reset state, while **Keep reset pose** leaves the saved baseline unchanged for temporary staging.

Every collider also has a **Collision skin** setting, in scene pixels. It is an invisible per-object contact margin: the two colliding skins add together, so it intentionally leaves a small visual gap while making fine, fast interactions more stable. Keep it small (often 0.5–2 px); it is separate from the visible Path chain thickness. Dynamic bodies run with Rapier CCD enabled by default, so fast objects are swept against their colliders rather than only tested at their endpoint. The debug overlay draws the effective path width and skin so diagnostic geometry matches the active solver shape.

1. Draw ordinary canvas objects and select them.
2. Assign one body role: Dynamic, Kinematic, Static, or Sensor. A body has one role, but may participate in any number of constraints.
3. Use the compact floating Physics toolbar for fast authoring. **Weld** and **Axle** turn selected canvas objects into authored pivot constraints. The pivot centre is tested against the physics bodies beneath it: one overlapping body attaches to World; two overlapping bodies join at that point; with no overlap the pivot remains detached for later endpoint assignment. A Weld may intentionally use one body plus `None` as a visual attachment, so an image, skin, or other canvas object follows that body's local anchor without being pinned to a synthetic world body. One-body Axles that contain a path endpoint snap to that visible endpoint when authored; reassign older Axles to apply that intentional correction. **Spring** uses the selected path's rendered start and end. A **Rope** starts as a free chain; tether it by creating an Axle or Weld pivot over any of its authored control points. The authored object owns its full constraint configuration at `object.customData.physics` and remains selectable, copyable, and deletable like any other canvas object. **Axle** rotates freely through 360° by default; opt into angular limits only when needed. The toolbar is draggable by its atom icon, can be minimized with Shift-double-click, closed with Option-double-click or its context menu, and reopened with `/physicstoolbar`. Its context menu can switch it between floating mode and a compact single-row top dock; that dock preference persists locally.
4. A **Rope** is not a special Rapier scene entity. It samples the authored line, arrow, freehand path, Bézier curve, or spline uniformly by arc length into a bounded set of short capsule links joined by revolute joints in the worker. The generated links never become canvas objects or serialize individually; the single authored path redraws from their solved endpoints. Its own endpoints remain `None`; any attachment is expressed by a separately authored Axle or Weld pivot, which may bind a body or World at an arbitrary rope control point. Rounded native paths are converted from their rendered smooth geometry, not from a sharpened fallback. **Link length** trades curve fidelity for solver cost, while the 96-link cap prevents raw pointer density from creating an unbounded simulation. **Thickness** sets the physical rope diameter without changing the source stroke. **Self collisions** is off by default and opts the rope into non-adjacent link contact; the layer matrix still controls rope-to-body and rope-to-rope contact policy, while **Collide while connected** only controls directly jointed neighbors. Run `/make rope` after selecting a compatible path.
5. Edit a named first-class constraint in the Physics panel's **Constraints** section or in the pivot object's Physics role in Properties. It exposes endpoints, enable/collide-connected state, and the relevant rope, spring, or hinge settings. Pin/Revolute/Weld remain compatible vocabulary for existing scenes; the persisted legacy `fixate` kind is displayed as **Weld**.
6. Press Play. Drag a running authored body directly to create a temporary grab spring; release it to return control to the solver without changing Reset.
7. Use Apply pose to author the current result, or Reset to return to the saved baseline.

### Actuators

**Attractor** and **Thruster** are authored canvas objects, not hidden solver-only handles. Their settings live with the authored object at `object.customData.physics`, while the relationship graph keeps their stable endpoint and system references.

- An **Attractor** uses its visual centre as a radial force origin. It can attract or repel dynamic bodies inside its radius, with strength, falloff, and optional comma-separated target tags. The attractor itself is not a collision body unless it is separately assigned a body role.
- A **Thruster** uses any two-ended canvas object. Its rendered start must overlap a dynamic body; its rendered end gives the force direction. The start's attachment and direction are converted to body-local coordinates, so its visible line follows the driven body as it rotates. A thruster pointing only at static bodies is rejected during authoring rather than silently doing nothing.
- An **Axle** can optionally enable a motor. Motor speed is authored in degrees per second and torque caps how strongly Rapier corrects toward that speed. Motors apply only to axle-style hinges; they remain independent of optional axle angle limits.

All three update inside the fixed physics step and never enter React's render loop. The diagnostics overlay can show their constraints and force vectors when enabled.

The inspector edits selected-body name, collision tags, friction, restitution, density, and damping. Population controls create seeded runtime instances and can materialize them as individually authored objects in one undoable change.

Curve sculpt commands use the same stable point resolver: Smooth, seeded Randomize, an Attract brush, and Morph. Morph arc-length-resamples the target for correspondence. One-shot operations are normal undoable geometry changes; an attract-brush drag becomes one history action.

## Collisions and mappings

Collision events include graph version, system, fixed step and simulation time, phase, collision class, both identities, population/instance IDs, object references, tags, point, normal, impulse, and relative speed. Default phases are `begin`, `hit`, `end`, and sensor `enter`/`exit`; broken constraints emit `constraint-break` / `break`.

Mappings run in the collision path outside React as `Source -> Filter -> Transform -> Target`. The first source adapter selects collision phase, class, tags, numeric field, and input range. Filters combine minimum/maximum thresholds and an optional safe boolean formula; transforms provide output range, scale, offset, clamp, and a safe numeric formula. Targets include MIDI Note, CC, Pitch Bend, direct Expressive Synth voices, and compatibility actions for old routes. Pair-gated Note and Expressive targets use stable mapping/body-pair keys so `begin` opens and matching `end` releases voices across all Mixer destinations. See [Generic mappings](mappings.md) for the complete schema, formulas, and target semantics.

## Public API

```js
const system = __.physics.systems.create({ name: "Gas", gravity: { x: 0, y: 0 } });
__.relations.mappings.create({
  source: { systemId: system.id, phases: ["hit"], classes: ["body-wall"], field: "impulse", range: { min: 0, max: 10 } },
  filter: { min: 0.2 },
  transform: { outputMin: 24, outputMax: 127 },
  target: { kind: "midi-note", channel: 1, note: 60, velocityExpression: "round(value)" },
});
await __.physics.play(system.id);
const stop = __.relations.events.subscribe(events => console.log(events));
```

`__.relations` provides graph CRUD, endpoint normalization, adapter registration/listing, collision streams, event subscription, and canonical mapping collections. `__.physics` provides system helpers, lists for bodies/populations/constraints/mappings, a legacy routes compatibility view, play/pause/reset/apply, impulses, grabbing, materialization, live poses, telemetry, and deterministic snapshots. Trusted script hosts also keep `__.api.relations` and `__.api.physics` as self-reference aliases.

- **Musical gas** draws curve and box walls, creates a seeded 250-particle runtime population, and routes body/body and body/wall hits to distinct sounds. See [Musical gas](examples/physics-musical-gas.md).
- **Marionette** creates persistent selectable rigid parts joined by a pin, spring, and revolute joints. See [Marionette](examples/physics-marionette.md).

It also demonstrates shared sculpt operators. See [Stream portrait and sculpt](examples/physics-stream-portrait.md).

## Performance telemetry

The existing monitor reports `physics.step`, `physics.transfer`, `physics.render`, body count, collision-event rate, dropped events, and route cost. The acceptance workload is the Musical gas example: 250 runtime bodies at a 60 Hz solver step while canvas rendering remains at least 45 FPS on the current target machine. Use a browser performance trace for CPU attribution; the overlay is cadence telemetry.

### Rope performance baseline

Rope cost is determined by its sampled solver links, not the number of points in the source drawing. Sampling is uniform by path arc length and capped at 96 links; a 1,200 px dense stroke with a 24 px link length creates about 58 links instead of hundreds of bodies and joints. Generated links share a private runtime collision group while **Self collisions** is off, which disables rope-internal contact pairs and avoids a quadratic contact workload. Authored bodies and walls listen to that private bit only when their named memberships and the world matrix allow contact, so a rope can be assigned to `ropes` and collide with a `spool` layer without touching itself. Enabling **Self collisions** returns the links to their authored layer groups and lets the matrix govern their internal contacts.
